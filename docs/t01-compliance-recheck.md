## 3. 브라우저 검증 순서

로컬 서버 실행:
```bash
cd ~/ALEPH/aleph-t01
git fetch origin
git switch --track origin/t01-compliance-first-screen
npm ci
npm run lint
npx tsc --noEmit
npm run build
npm run dev
```

- [ ] **1366×768**: 페이지 상단에서 Hero의 **소개 문장 + 대표 활동 + 클릭 가능한 근거**가 모두 보이는가?
- [ ] **1920×1080**: 같은 세 요소가 스크롤 전에 보이는가?
- [ ] 콘솔에서 `document.documentElement.scrollWidth <= window.innerWidth`가 두 해상도 모두 `true`인가?
- [ ] Hero의 Blog-frontend와 Digital Twin 논문이 시크릿 창에서 접근 가능한가?
- [ ] 강점 3개 상세 링크 각각 클릭, Tab, Enter, Space로 접근 가능한가?
- [ ] 개발자 도구 콘솔에 빨간 오류가 없는가?
- [ ] OS 움직임 감소 설정에서 아코디언·Hero·스크롤 모션이 생략되는가?
- [ ] 브라우저 접근성 검사(axe/Lighthouse 포함)로 전체 텍스트 대비율을 확인했는가?
- [ ] `/private` Passkey 등록/로그인/로그아웃 및 비로그인 401/403 회귀 테스트에 영향이 없는가?
- [ ] Git 기록과 배포 산출물에 비밀값 원문이 없는가? (`.env.example`의 placeholder는 검토)

## 4. 제출용 4줄 예시(C25) — 검증 후만 사용

1. **위치:** 배포된 공개 포트폴리오 URL의 첫 화면과 ‘강점’ 섹션.
2. **행동:** (1) 시크릿 창으로 열기 (2) 첫 화면 소개·활동·근거 확인 (3) Tab으로 강점 선택 후 Enter 또는 Space로 펼치기.
3. **통과 모습:** 두 해상도에서 세 요소가 첫 화면에 보이고, 링크·상세 내용이 클릭과 키보드로 열리며 콘솔 오류가 없음.
4. **안 될 때 모습:** 첫 화면에서 근거가 잘리거나 키보드로 상세를 열 수 없음. 실패한 해상도·키 입력과 콘솔 오류를 기록.

## 5. AI와 본인 판단 3줄(C26) — 사용자 검토용

1. **AI에게 맡긴 일:** 기존 코드와 기준을 대조해 Hero 정보 배치·명암·강점 링크를 수정하고 검증 체크리스트 초안을 작성하게 했습니다.
2. **직접 판단한 일:** 현재의 네이비/블루 포트폴리오 디자인은 유지하면서 재평가 조건을 별도 브랜치에서 충족하도록 수정하는 방향을 정했습니다.
3. **AI 제안을 따르지 않은 일:** 기존 사이트 전체를 단순 이력서로 되돌리지 않고, 마음에 드는 포트폴리오 디자인을 보존하기로 했습니다.
